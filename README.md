# 噪声分析测试小程序（MVP）

原生微信小程序初版，支持 iOS 和 Android 手机内置麦克风单通道采集；耳机采集模式已从产品范围中移除。

跨电脑继续开发时，请先阅读 [`DEVELOPMENT_HANDOFF.md`](./DEVELOPMENT_HANDOFF.md)。

## 启动

本项目是无 npm 依赖、无需构建的原生微信小程序。使用微信开发者工具直接导入仓库根目录即可；当前 `project.config.json` 已配置 AppID `wx4e4e4dd771fc9421`。启动后进入实时测试入口，点击“开始测试”才校验设备；通过后进入正式界面并请求手机内置麦克风权限。权限被拒绝或设备不适配时才弹窗提醒；正常状态不再显示设备与权限页。当前代码支持 iOS、Android 和开发者工具环境。

`project.ios.config.example.json` 和 `project.android.config.example.json` 分别作为两端测试模板，均使用同一个小程序 AppID；正式发布使用当前 `project.config.json`。

`project.private.config.json` 是微信开发者工具生成的机器本地配置，已被 Git 忽略，新电脑会自行生成。小程序沙盒中的录音文件、校准值、备注和标签也不会随 GitHub 同步；如需跨设备保留测试数据，应另行导出原始 WAV 和必要的记录信息。

跨电脑恢复代码的完整步骤、当前验证基线和待办事项见 [`DEVELOPMENT_HANDOFF.md`](./DEVELOPMENT_HANDOFF.md)。

## 已实现

- 启动后进入实时测试入口，首次点击“开始测试”后才校验设备；校验通过后进入正式测试并申请麦克风权限。正常状态不显示设备型号或权限状态，仅在 iOS 不适配或麦克风授权/启动失败时弹窗提醒
- PCM 实时帧解析、连续 7 Hz 高通、129 抽头 FIR 抗混叠低通、48 kHz 至 4 kHz 降采样、2048 样本 Hann 窗及 2048 点 FFT（1.95 Hz/bin、512 ms 数据窗）、RMS、数字峰值、削波检测
- 实时频谱和录音数据对比的横轴均可在 20–1000 Hz 内缩放。频谱支持线性/对数频率轴、A/线性计权、带数值的刻度尺、虚线网格，以及 dBA/dB 自动或手动纵轴范围
- 可将当前频谱设为会话内参考曲线，以橙色虚线与紫色实时曲线叠加显示；20–60 Hz、70–150 Hz、160–240 Hz 使用不同的半透明频带背景
- 可从本地 WAV 录音列表导入参考：使用与实时分析一致的 4 kHz 分析采样率、2048 点（512 ms）Hann 窗和 683 点帧移（约 2/3 重叠）计算功率平均 FFT
- 实时和参考频谱分别显示总声压级，以及低频（20–60 Hz）、中频（70–150 Hz）、空腔声（160–240 Hz）三个频带峰值；切换计权时曲线与全部指标同步重算
- 实时频谱使用 2048 样本窗和 683 样本帧移（约 2/3 重叠）；默认 1 秒平均固定为 3 帧。新帧到达时仅从功率和中减去最老帧并加入最新帧，平均时长可在 1–30 秒间调整
- FFT 计算约 5.86 帧/秒，图窗以最多 12.5 FPS 在相邻平均频谱之间做显示插值；插值帧不参与 FFT 平均或单值指标计算。最长 30 秒缓存使用增量功率和，固定纵轴时跳过自动范围扫描
- 频谱默认使用固定 `-80～-20 dB` 纵轴；绘图设置按“显示方式、显示范围、频谱平均、校准与参考”分组，计权、横轴线性/对数及纵轴自动/固定集中在显示方式中，横纵轴范围集中在显示范围中
- FFT 幅值按 Hann 窗相干增益归一化，避免使用矩形窗尺度造成约 `-6.02 dB` 的系统性低估；FFT 输入长度不是 2 的幂时会明确拒绝
- 频谱画布按手机卡片宽度和可用屏幕高度自适应，坐标字号与绘图区边距同步缩放
- 暂停时先更新交互状态并立即跳过后续 PCM 计算，暂停/继续按钮使用不同状态色
- 分析与录音分离：仅在用户点击“开始录音”后保存音频，每段最多 30 秒；录音时显示 0.1 秒精度的时长与进度，结束后以分块方式将 PCM 自动封装为 WAV，供文件参考与数据对比使用
- 录音保存成功后停留在实时分析页、显示成功提示并自动恢复实时分析，不再自动跳转详情；若因用户结束分析或输入中断而保存则不自动恢复
- 独立“数据对比”页可勾选最多 8 个录音；为兼容会忽略 `readFile position/length` 的微信基础库，最长 30 秒的 WAV 只读取一次，再在内存中按 64 KB 协作分块处理。离线分析与实时分析共用同一份 DSP 参数配置：48→4 kHz 降采样、2048 点窗、683 点帧移及 1 kHz 上限
- 数据对比任务令牌在页面加载时显式初始化为 `0`；这修复了首次递增得到 `NaN`、进度回调和最终结果全部被误判为过期任务、页面永久停在 1% 的问题
- 离线 FFT 跳过逐帧 RMS/峰值等无用派生计算；FIR 利用 129 抽头的对称性配对采样，将每个降采样输出的乘法次数减少约一半，实时与离线共用该优化
- 自定义底部导航使用加大字号，只保留“实时测试、录音文件、数据对比”三个入口，原首页和“记录”页已移除
- 独立“录音文件”标签页，集中显示文件格式、WAV 采样率、时长和大小；详情页保留元数据、数据对比和删除，不再提供音频回放。列表支持重命名，以及左滑置顶、取消置顶和删除
- 记录持久层只保存原始时域 WAV 及采样率、声道数、位深、时长、路径、文件大小、录音开始时的校准差值和用户填写信息等必要元数据；频谱和声级指标仅在数据对比时从完整 WAV 重新计算，不写入记录
- 录音详情页只显示源数据格式、时长、采样率、录音时间和录音时校准差值，不自动执行 FFT、不显示派生单值指标，也不创建音频播放器
- 实时绘图设置支持全局手动声压级校准修正（-100～100 dB）；例如输入 `+10 dB` 会使实时频谱和声级指标整体上移 10 dB，固定纵轴上下限也同步上移 10 dB。开始录音时会把该差值写入录音元数据；数据对比使用各录音自身的差值，不改写 WAV
- 记录详情支持本地重命名、备注和标签编辑；旧记录无需迁移即可继续查看和补充信息
- iOS 请求内置麦克风 `buildInMic`，Android 请求标准麦克风 `mic`；代码、界面、导航和新录音元数据均不再包含耳机模式、耳侧或耳机断连逻辑
- 采集启动使用可取消操作令牌；页面在授权或启动阶段隐藏/销毁时会使未完成的异步流程失效，禁止页面退出后继续启动录音器。异常超大 PCM 帧会限制为最多 128 KB 后再分析
- 无可信型号校准配置时只显示估计值，不将结果作为专业声级计读数

## 真机 PoC 待确认

- 微信在 iOS/Android 返回 PCM 的实际位深、字节序和采样率，以及 `buildInMic`/`mic` 的真实路由
- iPhone 与 Android 真机生成 WAV 后的时长、文件完整性及离线 FFT
- 每个目标设备的 FFT 延迟、丢帧与发热数据

本产品不作为经校准声级计使用。

手机型号可以用于选择参考修正配置，但不能仅靠检索“麦克风灵敏度”得到真实 SPL：同型号个体差异、麦克风方向、保护壳、输入路由以及微信/iOS 的增益和信号处理都会改变结果。绝对声压级应使用同一设备、同一路由与标准声源或已校准声级计进行现场校准；没有可信配置时继续标为估计值。
