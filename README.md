# 噪声分析测试小程序（MVP）

原生微信小程序初版，按策划书中的“单通道、手机/耳机互斥、以 dBFS 为主”的范围实现。

跨电脑继续开发时，请先阅读 [`DEVELOPMENT_HANDOFF.md`](./DEVELOPMENT_HANDOFF.md)。

## 启动

使用微信开发者工具导入本文件夹。当前 `project.config.json` 已配置 iOS 测试 AppID `wx4e4e4dd771fc9421`；请勿将这个文件用于 Android 版上传。

`project.ios.config.example.json` 和 `project.android.config.example.json` 是两个独立小程序的配置模板。发布时分别复制为 `project.config.json` 并填写各自 AppID 后上传。

## 已实现

- 首页设备/权限状态、手机与耳机单通道互斥选择
- PCM 实时帧解析、连续 7 Hz 高通、FIR 抗混叠低通、48 kHz 至 2 kHz 降采样、1024 样本 Hann 窗并零填充至 2048 点 FFT（0.98 Hz/bin、有效分辨率约 1.95 Hz）、RMS、数字峰值、削波检测
- 20–500 Hz 频谱绘图；频谱支持线性/对数频率轴、A/线性计权、带数值的刻度尺、虚线网格，以及 dBA/dB 自动或手动纵轴范围
- 可将当前频谱设为会话内参考曲线，以橙色虚线与紫色实时曲线叠加显示；20–60 Hz、70–150 Hz、160–240 Hz 使用不同的半透明频带背景
- 实时和参考频谱分别显示总声压级，以及低频（20–60 Hz）、中频（70–150 Hz）、高频（160–240 Hz）三个频带峰值；切换计权时曲线与全部指标同步重算
- 频谱约 20–24 FPS 刷新，并采用快速指数平滑、绘图请求合并、按屏幕像素合并绘图点和坐标范围缓动；FFT 旋转因子、Hann 窗及音频/DSP 工作缓冲区均复用，以减少垃圾回收导致的偶发卡顿
- 频谱画布按手机卡片宽度和可用屏幕高度自适应，坐标字号与绘图区边距同步缩放
- 暂停时先更新交互状态并立即跳过后续 PCM 计算，暂停/继续按钮使用不同状态色
- 分析与录音分离：仅在用户点击“开始录音”后保存音频，每段最多 30 秒
- 历史元数据、本地详情、顺序测量频谱叠加
- 耳机左右侧用户声明和未验证状态文案
- 无可信型号配置时不显示 iOS SPL；Android 始终只显示 dBFS

## 真机 PoC 待确认

- 微信上返回 PCM 的实际位深、字节序、采样率与 `audioSource` 路由
- 耳机断开事件和 AirPods/TWS 实际输入位置
- `PCM` 停止文件是否可直接播放；若不能，需接入流式 WAV 封装（不在内存累计整段 PCM）
- 每个目标设备的 FFT 延迟、丢帧与发热数据

本产品不作为经校准声级计使用。

| 项目 | 首测设备 | 需要现场记录的补充信息 |
| --- | --- | --- |
| 手机 | iPhone 16 Pro | iOS 版本、微信版本、基础库版本 |

Apple 将 A3063、A3064、A3065 归类为 AirPods Pro 3 系列。因此首轮测试记录会将 A3065 作为 AirPods Pro 3 兼容样本，而不是假定为 AirPods Pro 2。该信息只用于兼容性记录，不用于声压级校准。

首轮运行基线：iPhone 16 Pro、iOS 26.6.1、微信 8.0.76。AirPods 固件版本尚未记录，因此耳机采集默认视为“未验证”，且不显示参考 SPL。
